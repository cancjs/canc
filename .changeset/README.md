# Changesets

This folder holds changeset files, generated by running `npx changeset` whenever a change needs a release note.

Every file in this folder (other than `config.json`, `pre.json`, and this README) is a committed file that eventually becomes a published changelog entry.

## Writing Rules

- One user-visible effect per entry. Lead with what users experience rather than internal implementation details. Keep entries concise (one to two sentences). Extensive documentation belongs in package READMEs and guides.
- Do not add `(scope)` prefixes like `(toolbox)`. The package is already identified by the file frontmatter and target changelog.
- Do not include commit hashes, pull request numbers, or author handles. Changelogs are plain markdown without repository-specific links.
- Do not reference internal identifiers, private helper paths, or internal-only documents. Write for consumers of the published packages.
- Breaking changes must start with `**Breaking:**` followed by a concise migration note.
- Deprecations belong in their own bullet stating the deprecated name, the replacement, and planned removal at the next major release.
- Use normal public prose with straight quotes. Do not use em or en dashes, arrows, or non-keyboard characters.

Full changesets documentation: https://github.com/changesets/changesets
